⚗ Laboratorio práctico seguro

Ejercicios de razonamiento defensivo. Utiliza únicamente entornos locales, máquinas intencionalmente vulnerables o sistemas donde tengas permiso.

01 · Detectar SQL Injection

Identifica por qué concatenar entradas de usuario en consultas es inseguro.

Consulta insegura: SQL construido concatenando texto del usuario
Defensa: usa consultas parametrizadas, cuenta de base de datos con privilegios mínimos y errores que no expongan detalles internos.

02 · Detectar XSS

Evalúa el riesgo de insertar contenido no confiable en una página.

Entrada no confiable → renderizado en el navegador
Defensa: codifica la salida según su contexto, evita APIs DOM inseguras y utiliza una CSP como capa adicional.

03 · Evaluación de contraseñas

Introduce una contraseña ficticia. El análisis ocurre en este navegador.

No introduzcas contraseñas reales.

04 · Respuesta a incidentes

Secuencia inicial recomendada ante una sospecha de compromiso.

  1. Contener el impacto de forma segura.
  2. Notificar al responsable.
  3. Conservar evidencias y registros.
  4. Revocar credenciales comprometidas.
  5. Recuperar desde fuentes confiables.
